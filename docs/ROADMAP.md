# Roadmap: від прототипу до нативної гри

Ціль: **нативна гра для ПК (Steam)**. Браузерний прототип лишається інструментом для плейтестів і балансу.
Рушій за рекомендацією — **Godot 4 + C#** (обґрунтування в `RESEARCH.md`, розділ 4). Остаточне рішення фіксуємо в `DECISIONS.md` після фази 1.

## Фаза 0 — Браузерний прототип ✅
Перевіряємо, чи кор-геймплей веселий: відкидання, лава, спели, раунди з магазином.

## Фаза 1 — Плейтест, ТЗ і вибір рушія (1–2 тижні)
- 3–5 плейтестів прототипу з живими гравцями. Записати, що весело, що дратує, які спели імба.
- **GDD** (`docs/specs/GDD.md`):
  - кор-луп;
  - спели та їхні ролі (контроль / мобільність / шкода / захист);
  - режими;
  - мета-прогресія;
  - монетизація (лише косметика).
- **TDD** (`docs/specs/TDD.md`):
  - рушій;
  - мережева модель;
  - структура проєкту;
  - бекенд;
  - CI;
  - платформи.
- Візуальний напрям: 2D top-down чи 3D з ізометричною камерою, мудборд.
- **Технічний спайк (2–3 дні):** у Godot два клієнти й сервер рухають кружечки по мережі з передбаченням. Підтверджує вибір рушія до старту фази 2.

## Фаза 2 — Фундамент на рушії (4–6 тижнів)
- Структура рішення:
  - `Warlock.Sim` — чиста C#-бібліотека: детермінована симуляція, спели, фізика кіл, боти. Без залежності від Godot;
  - `Warlock.Sim.Tests` — xUnit: юніт-тести й масові симуляції ботами для балансу;
  - `game/` — Godot-проєкт: рендер, UI, ввід, звук, VFX;
  - `server/` — headless-збірка, що крутить `Warlock.Sim`.
- `data/spells.json` — дані спелів, перенесені з `shared/config.js`.
- Мережа:
  - ENet (UDP), 30–60 тіків;
  - клієнтське передбачення власного руху й узгодження із сервером (reconciliation);
  - інтерполяція інших гравців;
  - дельта-знімки.
- Steamworks (GodotSteam): лобі, інвайти друзів, Steam Networking Sockets.
- CI на GitHub Actions: тести симуляції, збірки під Windows/Linux, headless-сервер.

## Фаза 3 — Контент і реіграбельність
- 20+ спелів з комбо-взаємодіями (наприклад, лід + вогонь = пара).
- Різні арени: перешкоди, ями, рухомі платформи, різні форми звуження.
- Режими:
  - FFA;
  - команди;
  - King of the Hill;
  - «Картопля-бомба»;
  - драфт спелів;
  - рандомні набори.
- Мутатори раунду: випадкові події.
- Реліквії/перки між раундами (roguelite-шар): вибір 1 з 3.
- Звук, музика, «соковитість» ударів: хітстоп, тряска, частинки.

## Фаза 4 — Мета й соціальне
- Бекенд: Nakama або власний .NET + PostgreSQL. Акаунти, прогресія, відкриття спелів і скінів.
- Матчмейкінг за рейтингом (Glicko-2), приватні кімнати, спостерігачі, повтори (детермінована симуляція робить їх дешевими).
- Косметика: скіни магів, ефекти спелів, емоції.
- Хостинг виділених серверів: Hetzner / Edgegap / Hathora, регіон Європа.

## Фаза 5 — Реліз

- Ранній доступ → 1.0. Підтримка геймпада (Steam Deck).
